# Metrik

**AI-Powered CNC Predictive Maintenance for Zero Scrap.**

Metrik predicts CNC tool-wear probability from live spindle telemetry,
explains *why* with SHAP, estimates time-to-failure and scrap cost, and lets
an operator plan safe cutting parameters before a job starts. It is
**decision support only** — nothing in this app stops, throttles, or
reconfigures a machine. Every recommendation carries a confidence
percentage and is reviewed by a person.

## 1. Backend setup

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Train the model (reads data/predictive_maintenance.csv, writes .pkl + .json
# artifacts into models/). The CSV is already included in this folder.
python models/train_model.py

# Start the API
uvicorn api.main:app --reload --port 8000
```

The API is now live at `http://127.0.0.1:8000`. Interactive docs at
`http://127.0.0.1:8000/docs`.

If you ever want to watch raw simulated sensor JSON print to your terminal
independently of the API:

```bash
python utils/live_machine_simulator.py
```

## 2. Frontend setup

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. Vite proxies all `/api/*` calls to the FastAPI
backend on port 8000 (see `vite.config.js`) — no CORS/URL setup needed.

## 3. What you'll see

- **Dashboard** — 4 KPI cards (active machines, active warnings, avg.
  remaining life, scrap saved) and a live grid of 5 machine cards, polling
  the backend every 2 seconds. Click any card for the full detail view:
  a wear-probability gauge, a SHAP driver chart, live sensor readout, and
  the AI narrative box with a one-click JSON export.
- **Simulation** — the What-If sandbox. Move the Spindle Speed, Feed Rate,
  Depth of Cut, or Runtime sliders and the risk gauge + SHAP chart update
  live by calling `/predict`. Nothing here touches a real machine.
- **Reports** — export any single machine's full prediction record, or the
  whole fleet's status, as JSON.
- **Settings** — Dark / Light / System theme toggle and a short "how this
  works" note.

## Data & modeling notes

- Source dataset: Kaggle "Machine Predictive Maintenance Classification"
  (`backend/data/predictive_maintenance.csv`, included).
- Columns renamed to CNC terminology: `Rotational speed [rpm]` → `Spindle
  Speed [rpm]`, `Torque [Nm]` → `Feed Rate [Nm]` (torque used as a proxy for
  mechanical load), `Tool wear [min]` → `Cumulative Tool Runtime [min]`.
- Engineered feature: `Material Hardness Index` (L=1, M=2, H=3) from `Type`.
- Model: XGBoost classifier on `StandardScaler`-scaled features, with
  `scale_pos_weight` set to correct for the dataset's ~3.4% failure rate.
  Test ROC-AUC ≈ 0.97 on the included dataset. Outputs a probability
  (0–100%), never a hard 0/1.
- Explainability: SHAP `TreeExplainer` on every prediction, surfaced as a
  ranked, normalized contribution-percentage list.
- **Sensor flexibility**: `backend/utils/sensor_config.py` defines a
  fallback per feature — missing readings fall back to the training median,
  or (for Feed Rate specifically) are estimated from Spindle Speed and
  Runtime. The app never crashes on an incomplete sensor payload; the UI
  marks estimated fields with a small info badge.
- Cost impact is a mock formula for the demo: `risk% × $150 / 100`.
- The chatbot narrative is fully mocked with deterministic Python logic
  (no API key, no network call) — swap `chatbot_mock.py` for a real Azure
  OpenAI call later without changing its return shape.

## Design notes

Dark mode by default (with Light/System toggle), glassmorphism cards,
Poppins for display type, Inter for body text, and JetBrains Mono for every
numeric telemetry readout so sensor values read like an instrument panel.
The signature mark is a machined dial/gauge motif that recurs in the logo,
the risk gauges, and the range-slider thumbs.
